## Quick start

```bash
remote=$(git remote get-url --push --all origin) &&
test "$(printf '%s\n' "$remote" | wc -l)" -eq 1 &&
case "$remote" in
  git@github.com:*|ssh://git@github.com/*) command -v connect ;;
  *) printf 'Expected one GitHub SSH push URL\n' >&2; false ;;
esac &&
branch=$(git symbolic-ref --quiet --short HEAD) && git rev-parse --verify HEAD &&
GIT_SSH_COMMAND="ssh -o ProxyCommand='connect -H 127.0.0.1:7890 %h %p'" git push -u origin "$branch"
```

Prerequisites: origin has exactly one GitHub SSH push URL; the current branch has commits; the SSH key is authorized; connect supports -H; the proxy supports HTTP CONNECT to the SSH endpoint. Check the actual protocol/port first. The chained quick start stops on failed prerequisites. Review any first-use host key against GitHub published fingerprints. This example does not create a repository or change remote URLs.

Inspect the actual push URL, not only the fetch URL. Continue only with one GitHub SSH destination and a connect helper supporting -H (HTTP CONNECT). The quick start chains prerequisites with && so failures prevent pushing. HTTPS needs a different proxy/authentication workflow. Do not assume connect is installed.

### 2. Read the actual current branch and confirm a commit exists

```bash
branch=$(git symbolic-ref --quiet --short HEAD) && git rev-parse --verify HEAD
```

Stop on failure. A detached HEAD or branch without commits needs attention before pushing. Branch names may be main, master or something else; Git Bash does not choose them.

### 3. Push using an explicit SSH ProxyCommand

```bash
GIT_SSH_COMMAND="ssh -o ProxyCommand='connect -H 127.0.0.1:7890 %h %p'" git push -u origin "$branch"
```

The SSH command receives the HTTP CONNECT proxy explicitly for this operation. Git http.proxy does not configure SSH. A SOCKS-only proxy requires a different helper option and must not be used with -H.

## Pitfalls — what NOT to do

Separate the observed symptom from the explanation; do not infer causation
from a later successful attempt alone.

| Dead end | Recorded cause or hypothesis | Observed symptom |
|----------|------------------------------|------------------|
| Set git http.proxy and assume an SSH remote is proxied | HTTP(S) proxy configuration does not configure the SSH transport | SSH still attempts a direct connection; a timeout alone does not prove the cause |
| Run git push origin main or master without checking the branch | The named local ref might not exist, or the branch might have no commits | src refspec does not match any |
| Treat a successful ls-remote as proof the push uploaded this commit | Reading remote refs only proves read access; the expected ref and commit must match | Remote query succeeds while the intended branch is absent or points at an older commit |
